# iCE40 Probe

Host-side experiments for classifying iCE40UP5K logic-tile configuration
coordinates, measuring the structural effects of single-bit flips, and building
known-answer LUT-inversion probes for an iCESugar v1.5 board.

The question behind it: on a device with **no published CRAM readback flow**,
can a device-local map be used to build a mutation operator that is more
conservative and more auditable than raw bit flipping?  See
[`docs/findings.md`](docs/findings.md) for the bounded answer.

## What this found

- **A bounded structural safety argument needs no silicon and no readback.**  The
  coordinate census covers 660 logic tiles x 864 coordinates; the routing sweeps
  then enumerate -- rather than sample -- every flip that enables a routing path
  in the 137 and 596 non-empty tiles of the two fixtures.  It is a statement
  about the database's structure, not about silicon.
- **Decode before you program.**  A LUT-index bug that silently turned a
  combinational output into a registered one was caught by decoding the mutated
  bitstream back to a netlist -- not by any readback, which would only have
  confirmed that the intended bits were written.
- **A known-answer probe must be shown to be discriminating before it is
  programmed.**  A first probe inverted a counter's MSB; the resulting colour
  cycle was a rotation of the baseline and therefore indistinguishable by eye,
  so its null result was uninterpretable.  `mkprobe.py` now refuses such probes.
- **A hard-IP source can be missing from the graph entirely.**  A PLL-driven
  global network had no driver at all in the model, so any second source added
  to it produced no conflict -- a whole class of false negatives invisible to
  fixtures that instantiate no hard IP.

The quantitative results are relative to the installed Project IceStorm
database. A "global multi-driver candidate" is a prediction from a split-aware
configured-net graph, not a direct electrical measurement on silicon. Its
driver whitelist covers LUT combinational, sequential and carry outputs,
IO-input, RAM-read, and UP5K DSP outputs, plus configuration-derived hard-IP
sources: `make pll-check` exercises UP5K `SB_PLL40_2F_PAD` port A's global path
and port B's core path, `make spram-check` one `SB_SPRAM256KA` read-data port,
`make osc-check` the HFOSC-driven global network and both oscillators'
direct fabric outputs, and `make i2c-check` the fifteen fabric outputs of each
of the two `SB_I2C` instances.  Hard-IP coverage is therefore partial -- PLL
port A's core path, the other PLL variants, the SPRAM write path and its other
three instances, and the LFOSC global are not exercised, and what either of the
two `I2C_ENABLE` bits means on its own is recorded as undetermined rather than
guessed.  `make hard-ip-inventory` surveys the rest: SPI (25 fabric endpoints)
and LEDDA (4) drive the fabric and are not modelled yet; RGBA drives package
pins only and is not applicable to the driver graph.  LEDDA has no enabling bit
in the published configuration, so whether it is a source at all is recorded as
undetermined.
`glb_netwk_*` is never treated as a source; it is a distribution network.

## Requirements

- Python 3.10 or newer
- Project IceStorm (`icebox`, `icepack`, `icebox_vlog`)
- Yosys
- nextpnr-ice40
- Icarus Verilog

If IceStorm's Python module is not installed in a standard system directory,
set `ICESTORM_PYTHON` to the directory containing `icebox.py`.

The checked environment used Yosys 0.33, nextpnr 0.6-3build5, Python 3.12.3,
and Icarus Verilog 12.0. Run `make versions` to record the local versions.

## Reproduce

```sh
make all
make test
make analyze
make verify-repro
```

Build products and fresh logs are written to `build/`. `make verify-repro`
checks that the current toolchain recreates the checked-in ASC and BIN fixtures
byte for byte.

The intentionally ambiguous mut2 probe is a negative fixture. `mkprobe.py`
returns failure for it unless `--allow-indistinguishable` is explicitly used.
The valid mut3 probe is regenerated by `make probes`.

### Optional: independent oracle

These are **not** part of `make test`.  Run time ranges from a few minutes for
the 500-flip sample to 14.7 hours for the dense adds-only sweep (203,986 flips
on 16 workers); the leds adds-only sweep takes about 86 minutes.  Every checked flip is appended to a JSONL file that records the
ASC hash, IceStorm version, scanned coordinates, oracle positives, and any
model/oracle disagreement, so an interrupted run resumes by re-running the same
target.  A resume is refused if the ASC hash, the IceStorm module, the model
sources (`oracle.py`, `exhaustive.py`) or the sampling parameters differ from
the recorded header.  Results are written to `results/`, not `build/`, so that a
clean rebuild cannot destroy hours of sweep evidence.

```sh
make oracle-leds           # 500-flip sample, a few minutes
make oracle-leds-full      # all adds-only flips on the leds fixture
make oracle-leds-addrem    # the leds add+remove class
make oracle-leds-report    # acceptance gate for a finished leds sweep
make oracle-dense-full     # all adds-only flips on the dense fixture (~14.7 h)
make oracle-dense-addrem   # the dense add+remove class
make manifest              # regenerate the evidence manifest
make archive               # compress the completed sweeps
```

The oracle exits non-zero if the model and the oracle ever disagree.
`--report` re-reads a result file and checks coordinate completeness and
uniqueness, that every positive raises the conflicting-net count by exactly one,
that the positive count matches `--expect-positives`, and that no verdict
disagrees; it also drops a half-line left by an interrupted run and rewrites the
file so the next resume appends cleanly.

## Important files

- `work/bitclass.py`: IceStorm-relative coordinate census and deterministic sampling.
- `work/muxmodel.py`: sampled local routing-entry effects.
- `work/exhaustive.py`: exhaustive local effects plus split-aware global driver graph.
- `work/oracle.py`: independent cross-check of those verdicts.  It re-implements
  flip enumeration, mutates the configuration in place and rebuilds IceStorm's
  entire segment graph per flip, sharing no conflict logic with `exhaustive.py`
  (which it imports only to compare verdicts).  `glb_netwk_*` is treated as a
  distribution network, not a source.
- `work/hard_ip_inventory.py`: the survey step run before any identity is
  written.  `icebox.extra_cells_db` is the authority on where a hard IP meets
  the fabric and on its enabling bits; the synthesised designs check that
  database rather than standing in for it.  Reading a count off a design instead
  is how this file first reported 19 SPI endpoints when the device has 25 -- the
  fixture drove one chip select out of four.
- `work/carry_check.py`: the gated `lutff_N/cout` identity, and the exact
  enumeration -- 660 tiles, 4,620 carry sources, 5,280 `in_3` muxes -- that
  proves adding it cannot change a verdict.  It also recomputes both fixtures'
  positive coordinates and diffs them against the archived sweeps in both
  directions.
- `work/manifest.py`: writes the evidence manifest, and with `--check` fails
  when it no longer describes the tracked tree.  `--self-test` proves that gate
  fires; a guard that has never failed proves nothing.
- `work/tile_coverage_check.py`: guards the enumeration itself.  Two defects
  here produced a clean-looking negative from an incomplete list -- the second
  concluded that `CLKHF_DIV` left no trace in the ASC, when it lives in the one
  tile collection the list omitted.  Scripts now iterate through
  `iceutil.configuration_tiles`, any collection an `iceconfig` exposes must be
  iterated or named as non-tile configuration with a reason, and the regression
  keeps the old list around as the failing case.
- `work/mkrouteprobe.py`: checked host-only generator for a single routing-risk probe.
- `work/guarded.v`: switch-gated routing experiment with three PMOD2 analyzer probes.
- `work/guarded_tb.v`: verifies safe reset, 32/64 predicted mismatch duty, and recovery.
- `work/mkprobe.py`: safe LUT inversion and observational-discrimination gate.
- `work/tb.v`: forced-state gate-level checks for baseline, mut2, and mut3.
- `work/top.pcf`: minimal constraints for the two top-level designs.
- `work/io.pcf`: full board pin reference; not used for these builds.
- `docs/findings.md`: bounded conclusions and board-observation record.

No build or test target programs the FPGA. Any future board operation should be
announced and separately authorized before it is run.

`make route-probe` generates the selected routing-risk artifact under
`build/physical/`; it does not contact the board. Use
`python3 work/exhaustive.py --details build/leds.asc` to audit all candidates,
their post-mutation drivers, and the affected route endpoints.

`make guarded-test guarded-route-probe` builds the guarded baseline and its
single-routing-bit mutant. These targets are host-only. The guarded design uses
SW0 as an active-low experiment enable and exports enable/source/destination on
PMOD2 pins 1/2/3; opening SW0 returns all counter registers to zero.

## Latest board verification

On 2026-08-22 the safe baseline and LUT-INIT-only mut3 probes were programmed,
read back byte for byte **from the external SPI flash** (the device has no
published CRAM readback flow; this is a flash-content check, not a
configuration-memory one), and their LED sequences were observed as predicted.
No routing-risk candidate was programmed because no current measurement was
available. The board was left with the same `leds_mut3.bin` image it had at the
start. See `docs/findings.md` for hashes and evidence boundaries.

## Scope

This project checks that Project IceStorm's and nextpnr's published model of
iCE40 UltraPlus routing and driver representation is self-consistent.  It is
not security research, it does not analyse undocumented bitstream content, and
it is not chip reverse engineering.  Where this project's own coverage is
partial that is stated rather than glossed over: the sweeps enumerate only flips
that enable a routing path in non-empty logic tiles, hard-IP coverage extends to
one PLL configuration, one SPRAM instance and the two oscillators, three further
blocks are surveyed but not modelled, and no claim here has ever been checked
against silicon.

## Evidence that is not in the repository

`results/*.jsonl` holds one record per checked flip and runs to several MB per
sweep, so those files are generated locally rather than tracked.  The run logs
and acceptance reports beside them are tracked, and every number quoted in
`docs/findings.md` cites is reproduced by the `oracle-*` targets above; the
document itself is written by hand and is not generated.  Each result
file records the ASC hash, the IceStorm module hash and package version, and the
SHA-256 of both model sources, so a stale file cannot silently be resumed after
the model changes.

What *is* tracked is `docs/evidence_manifest.md` (`make manifest`), which
re-runs the three hard-IP fixture checks and records, for every sweep, the
SHA-256 of the file, the hashes it was produced against, the counts, and the
coordinates of every oracle positive.  `results/archive/*.jsonl.gz`
(`make archive`) is tracked too: the sweeps compress about forty-fold, so the
raw evidence fits in the repository rather than living on one machine.
